# 故障排查

## 升级后面板请求旧版 client.js

报错地址带旧扩展版本，而 Core 已加载新包时，可能是已打开的设置页保留了旧 provider 信息。升级后旧资源地址返回 404 并不等于本机配置或角色素材损坏。

1. 浏览器中刷新整个 Core 页面，不只是点衣橱内部“刷新”。
2. 原生应用中关闭设置窗口，再从托盘或桌宠菜单重新打开“设置”，让页面重新创建。关闭该窗口会保留 Core 和桌宠运行；重新启动程序文件可能只显示桌宠，因此使用真正的“设置”入口。
3. 仍失败时，在 World 扩展中检查安装／实际加载版本、本机服务连接，以及当前版本 client 资源是否可访问。记录新旧地址和报错，不公开个人配置。

脚本本身没加载时，扩展无法执行自己的“修复”按钮。不要因此删除个人衣橱、修改宿主程序或清空所有应用数据。原生 Ctrl+R 不一定能刷新嵌入页面。

## 桌宠未连接／预览缺失

检查本机桌宠服务和扩展中的连接地址，修改地址后重启本 World。缩略图应由已安装包声明、位于其资源目录内，并是小于 2 MiB 的合法支持图片。预览缺失不会自动补出动画素材。

## 配置通过，但动画不完整

衣橱校验只检查语法、选项引用、已安装 scheme，不验证运行时所有动作／表情是否齐全，也不判断视觉质量。要先完成形象包并观看原速／半速。仅导入 JSON 不能修复角色或创造新服装。

## 恢复外观未完成

保持桌宠服务和旧角色可用，再点恢复。正常停用只恢复仍由扩展接管的外观，保留原生页另做的选择；强制关进程或服务不可用时，可能下次启用才恢复。卸载前确认恢复成功，不要第一步就手工删除恢复记录。
