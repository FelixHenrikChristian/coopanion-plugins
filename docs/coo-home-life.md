# coo家园：操作与交互

生活阶段复用已批准的街区、房间和家具。角色的位置、任务和生活状态由家园 World 独立管理；原桌宠不接收这些移动或动作指令。

## 使用方式

- 单击家具，动作按钮会出现在物件旁边，并随视角移动；靠近窗口边缘时自动避让。点击按钮后，角色先沿可达路线走近，再开始活动。按 Escape 或点击空白处可以关闭选项。
- 勾选“排在当前任务之后”可以排队；不勾选时，新指令替换当前安排。
- 单击有足够空间的地面可以走到该处。拖拽仍用于旋转场景，墙面与家具表面不会当作地面目的地。
- “暂停生活”冻结生活进度、任务和作物生长；“继续生活”从暂停位置继续。“取消任务”清空当前安排和队列，并给自主行为留出短暂间隔。
- “自主生活”让角色根据精力、饱腹、整洁和舒适状态安排休息、阅读、用餐等日常活动。此阶段使用本地规则，不调用 AI。

房间的墙面显示方式不改变通路。角色可在住宅、缘侧、菜园道路及连接它们的人行道活动；街对面的商店目前仍是街景。

## 家具能力

场景保留原来的 **32 个家具点和 8 块菜畦**。生活菜单提供 **94 个动作入口**：家具的 62 个动作，以及每块菜畦的查看、播种、浇水和采收。

| 类型 | 当前实际表现 |
| --- | --- |
| 行走 | 绕过墙、固定家具、菜床与分隔栏；通过真实门洞和入口台阶。 |
| 坐下与休息 | 使用角色包已有的坐姿或睡眠动作，配合座位位置与朝向；缺少对应姿态时留在安全站位，使用已有动作休息。 |
| 电视、电脑、床头灯 | 角色到达并完成开关任务后，实际改变屏幕或灯的可视状态。 |
| 洗衣机 | 角色到达并开始洗衣后显示运行指示，结束或取消时停止。 |
| 阅读、喝茶、用餐、备餐、洗漱等 | 走近对应家具，播放已有可用动作，展示任务进度并结算独立生活状态。没有生成拿筷子、切菜、刷牙等新角色动画。 |
| 衣柜、鞋柜、伞篓等 | 提供收纳、检查与准备活动；本阶段没有实体柜门动画、衣物库存或新的换装逻辑。角色外观继续跟随宿主的选择。 |

菜单的活动名称表示任务内容，并不声称每项都有独有的角色动画。活动被接收、走到物件旁边、活动完成是三个不同阶段；生活状态与使用记录只在完成后结算。取消或替换会单独记录，不冒充完成。

## 八块菜畦

新家园从八块空田开始，每块田都能选择任意一种作物。点击菜畦旁的“播种”，在选择窗口查看作物和成熟时间，再点选开始安排。关闭选择窗口不会播种。采收后可以换种，不再把作物固定在某块田。

播种后等待第一次浇水，再开始计时生长。之后浇水只更新土壤湿润程度，不重置成熟时间。没有枯萎、金币、买卖或新物品库存；采收累计次数会保存。

| 可选作物 | 首次浇水至成熟 |
| --- | --- |
| 小葱 | 30 分钟 |
| 白萝卜、胡萝卜 | 45 分钟 |
| 卷心菜、黄瓜 | 60 分钟 |
| 番茄、茄子 | 75 分钟 |
| 甜椒 | 90 分钟 |

点击菜畦后，选项下方显示作物、阶段、生长比例、预计剩余时间与采收次数。空畦、已播种、幼苗、生长中、成熟都有对应表现；床体与街区布局保持原样。植物、适用的支架和作物牌复用场景已有模型，随选择的作物切换；空田隐藏这些种植物件。

角色先走到菜畦旁，再执行动作；播种、浇水和采收在任务完成时生效。可以勾选排队，依次安排“采收 → 播种 → 浇水”。排队时允许后续阶段的指令，真正开始和完成时会再次核对状态；重复采收或失效任务会取消并说明原因，不会虚增收获。

本地自主规则只会给已经播种、等待首次浇水的菜畦补水，优先满足室内生活需要，最多每五分钟安排一次，不自行采收或播种。另行开启可选 AI 自主计划后，AI 也能选择播种、浇水或采收。关闭自主生活后，已经开始生长的作物仍按时间成熟；“暂停生活”才会冻结生长。

## 关闭页面与存档

关闭家园页面后，场景和角色停止绘制，家园音频立即停止。仍启用的 World 使用已准备的路线和活动时长继续规则模拟，不进行逐帧绘图或反复网格寻路。

完全退出 Coopanion 后不运行后台进程；重新打开时，根据存档时间补算。离线计算最多详细推进 24 小时、256 次阶段转换，超出部分以有界估算处理，并标记为近似结果。自主生活开启时，长离线的近似结算会把生活状态恢复至至少 55/100。暂停状态会保存，离线期间也保持暂停。

存档位于宿主部署的数据目录下的 `coo-home` 子目录。命令在成功写入后才确认；活动阶段变化及定期检查点也会保存。原子替换、上一版备份和中断写入文件用于恢复。未来版本的存档或全部损坏的存档会阻止自动覆盖，避免回退插件时丢失进度。

存档包含家园位置、任务、生活状态、家具状态及八块菜畦的作物、种植时间与采收次数，不包含角色名称、标识、图像、服装配置或桌面聊天历史。当前格式为 3：升级保留原有位置、生活状态和已种植的真实进度；旧版从未播种、从未采收的默认成熟植物改为空田，已获得的采收计数保留。旧队列中没有作物选项的播种任务沿用当时该田的作物。离线作物按时间结算，同一批作物重复读取不会反复增加成熟或采收事件。

## 家园对话与声音

打开右上角“家园对话”，可以聊天，也可以说“去喝杯茶”“给播好的菜浇水”等指令。模型使用家园的物件目录和当前进度选择动作；接收指令只表示已开始安排，角色仍要走近并完成活动才结算。鼠标操作与聊天使用同一套任务和校验，不会绕过菜畦阶段或家具碰撞。

新的鼠标或桌面指令优先于较早对话里尚未执行的操作。旧对话可以继续回复文字和查询状态，但不能晚到后覆盖新安排。

家园在每次新对话时沿用 Coopanion 当前选择的模型服务、模型参数和人格正文；同一轮工具执行期间保持该选择。用户无需另填密钥，认证仍由官方 provider 管理。人格只读，不修改宿主的人格文件，也不读取桌面会话历史或关系记忆。家园聊天保存到独立的 `chat.json`，不会自动加入桌面聊天。

`alpha.5` 修正了 Responses 兼容服务立即拒绝家园请求的问题：本地对话收据编号不再作为服务端消息编号发送。更新后可直接继续旧聊天，无需清空历史。服务仍报错时会显示安全的 HTTP 错误类别，不输出请求正文、密钥或原始响应。

“停止回复”终止模型生成与尚未执行的工具请求，已经接受的家具任务继续运行；取消这些任务应使用生活面板的“取消任务”。“清空记录”只清除家园对话，不重置家具、菜园、每日额度和桌面汇报去重记录。重开后不会自动重放未完成的模型请求或工具操作。

关闭页面不会取消已经明确提交的手动对话，它可以完成必要的工具续答并保存结果；重新打开只显示历史，不补播声音。停用家园 World 或退出宿主才会中止在途模型请求。

声音沿用宿主当前角色声明的声音与宿主音量设置。首次在家园里点击或按键后，浏览器才解锁声音。开启宿主音节语音时使用官方音节声音，否则使用当前角色已有的说话音效；没有相应声音时保留文字回复。一次朗读最长约 40 秒，不制作新角色音频。

家园有自己的音频实例。隐藏页面立即停播，重新显示不补播隐藏期间的回复；换角色或停用插件会丢弃旧声音。朗读只控制家园里的独立角色，不让原桌宠替家园播放整段对话。

## 自主 AI 与桌面汇报

“自主生活”是生活面板中的开关；“AI 自主计划”是对话面板中的可选增强，需要同时开启自主生活。关闭自主生活也会停止启动新的 AI 计划。AI 默认关闭，关闭 AI 不会停止已开启的日常规则活动。开启后会根据当前家园状态，偶尔选择一项活动；手动指令优先，已经过时的计划不再执行。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| AI 自主计划 | 关闭 | 开启后允许家园在页面关闭时调用模型安排生活。 |
| 计划间隔 | 30 分钟 | 可设 5–1440 分钟；手动任务或暂停状态会延后计划。 |
| 家园自主请求上限 | 每天 12 次 | 可设 0–100；每轮工具续答也计一次请求，耗尽后继续本地规则生活。 |
| 桌面重要活动转达 | 开启 | 只发送作物成熟、采收等简短状态，不转发完整家园对话。 |
| 主动汇报上限 | 每天 4 次 | 可设 0–24；主动汇报至少间隔 15 分钟，并合并期间的事件。 |

家园请求上限按家园主动发起的模型请求计算，发送前保存额度；模型服务内部重试不受插件逐次控制。手动聊天不受自主请求额度限制。桌面主动汇报会唤醒宿主主会话，其后续模型请求由宿主管理，不能把一次唤醒等同于一次模型调用。

家园页面可见时，重要活动可主动唤醒桌面桌宠汇报。页面关闭且 AI 自主计划未开启时，消息只排队等待桌面下次对话带出，不主动唤醒模型；开启 AI 后，后台重要汇报也可在限额内唤醒桌面。关闭转达开关则不发送。汇报事件有持久化去重，重新打开不会反复报告同一批收获。

也可以直接在原桌宠的对话里让它查看家园或安排活动。宿主可调用 `coo_home` 工具读取状态、查看目录、安排动作、取消、暂停或继续家园。工具回执明确区分接收、排队和完成；这些操作不移动原桌宠、不更换原桌宠形象，也不改变它的生活状态。

完整实施和验收进度见[开发路线](coo-home-plan.md)。

## 已完成的生活阶段验收（alpha.2）

- 40 处目的地、70 个动作的路线与阶段转换通过检查；任务接收、抵达与完成分别验证。
- 实际浏览器中确认连续行走、五处座位可见、床边动作替代及电器状态变化。四种墙面视图不改变碰撞规则。
- 暂停跨过原任务完成时间仍保持位置和进度；手动抢占、排队、取消与重新打开存档均有回归检查。
- 页面隐藏时，场景与角色帧数停止；五分钟的测试时钟推进仍执行规则活动，没有调用详细路线计算。
- 正式 Coopanion Core、console 和官方 Figure kit 的隔离运行通过角色行走、暂停、换角、重连与存档恢复验证。

- 默认独立场景与上一已推送版本的画面几乎相同。角色验收只使用中性几何素材，未读取私人角色。

## 对话、语音与整体回归（alpha.4）

- 在未修改的 Coopanion 0.2.20 Core、console、官方 Figure frame 中，使用隔离部署与合成 provider 验证当前模型参数、只读人格、密钥入口和模块管理的认证状态。SDK 保持宿主同一运行时；没有复制认证实现，没有调用真实付费模型或读取私人角色素材。
- 家园聊天没有进入桌面 session 或事件，桌面输入没有写进家园聊天。正式桌面聊天通道确实调用 `coo_home`，并收到“已接受、尚未完成”的任务回执。
- 另以真实行走和采收完成验证反向链路：正式 Core 保存 `coo-home.garden`，唤醒主会话，经过实际 `pet_say` 工具产生桌面说话事件和气泡。汇报没有包含家园私有聊天，也没有移动或换装原桌宠；World 停用重启后仍只保留一次汇报与一次唤醒额度。
- 真实浏览器验证流式回复、停止、纯文本显示、独立清空和设置保存。关闭页面后已提交的手动回复正常保存，不发声，重开不补播。
- 旧聊天晚到、聊天首次保存延迟、重复客户端请求、重复工具编号、AI 与手动指令并发、启用与停用并发都经过回归。停止 World 会中止在途模型并等待其资源结束；不合作的 provider 不会被标记为已正常结束。
- 实际 SDK 请求验证默认 AI 关闭时零自主调用，每次工具续答计入请求额度，额度写入失败时不发请求。主会话唤醒额度与家园请求额度分开；报告冷却、关页只排队、重启和写入中断去重均通过。
