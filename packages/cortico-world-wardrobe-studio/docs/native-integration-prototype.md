# 原生装扮页集成 · 隔离原型

## 状态

此原型验证“原生装扮页 → 服装 → 当前服装的部件选项”的交互。**这是 0.3 开发阶段的历史原型；0.4 的可选兼容实现见[正式设置说明](native-integration.zh.md)。** 此原型本身没有安装到真实 Coopanion，也没有修改其程序或角色文件。

原生页目前直接遍历角色包的 axes/options，没有供外部 World 接管这一块的正式接口。原型在独立 HTTP 服务中只读加载本机原生页面，对发送给浏览器的 dress.js 副本增加一个明确的渲染钩子；磁盘上的源文件保持不变。没有把未知脚本注入正在使用的窗口。

## 验证的交互

| 场景 | 预期行为 |
| --- | --- |
| 已启用，角色有合法衣橱配置 | 隐藏原配置轴，显示服装与该服装自己的部件 |
| 没有资源的组合 | 对应部件选项禁用 |
| 换到无配置角色或 Coo | 保留其原生控件 |
| 停用、模拟卸载或提供方离线 | 恢复原配置轴与完整搭配列表 |
| 选择已有搭配 | 原生预览切换，预览 iframe 保持存在 |

原型中的外观修改只写入该进程的内存。停用集成只撤回分组 UI；已经选中的合法 scheme 仍可由原生页显示。未来正式原生集成应将用户点击视为宿主的普通装扮选择，不依赖插件文件才能继续播放。独立衣橱面板已有的外观接管／恢复机制保持其原有定义。

## 运行

需要现有的 Node.js 与已安装 desktop-pet 包。脚本复用该包已有的 ws 模块，不下载依赖、模型或角色资源。

```sh
node prototypes/native-dress/server.mjs --web "<desktop-pet 包的 web 目录>" --port 65088
```

浏览器打开终端打印的回环地址。默认使用 Coo 和噜噜衣橱预览。噜噜预览只使用四张已验收静态图，轻微待机仅用于检查界面；完整连续动作请使用独立噜噜角色包。

页面上方可模拟启用、停用、卸载、重新注册及接口离线。原生安装／删除入口在隔离服务中不可用。

也可以明确指定自己的私有配置及本机角色资源目录：

```sh
node prototypes/native-dress/server.mjs --web "<desktop-pet/web>" --profile "<私有 wardrobe.json>" --figure-root "<本机 figures 目录>" --seed "http://127.0.0.1:7797" --port 65089
```

此模式只在启动时 GET 读取本机形象列表和外观，之后使用隔离内存状态；角色文件只读、按需加载，不复制整套素材。个人配置、截图、日志和绝对路径不要提交到公开仓库。

## 原型边界与正式接入

此原型用于检查服装／部件切换、原生预览、Coo 配件保留、停用、模拟卸载、重新注册和接口离线回退。另在隔离状态中检查了已有本机角色及不完整组合禁用；个人配置和该轮截图不在公开仓库中。安装目录的原生源文件哈希保持不变。

- 复制页中的渲染钩子不是现有 World API 的能力。正式接入需要 desktop-pet 或 Coopanion 增加受控接口。
- 建议宿主接收声明式衣橱配置，由宿主校验 figure/scheme 并绘制控件；提供方失效时立即回退原 UI。
- 资源选择继续由宿主外观接口保存，保留原生预览、其他角色与 Coo 配件。
- 提供方注册、撤销、冲突优先级和当前角色作用域需要正式定义；不靠全局 DOM 注入或修改角色 manifest 接管界面。
- 脚本检查原生源文件的三个明确锚点。源版本改变时会停止，需人工复核；这不是承诺所有宿主版本兼容的安装器。
- prototypes 目录不在 npm 发布文件清单中。这里的开发原型不会随着当前插件包自动执行。
