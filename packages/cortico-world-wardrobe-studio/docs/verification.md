# Verification

## Package 0.6.0

Independent-panel release: the host patch adapter, restoration utility, feed, helper clients, configuration switches and native-page prototype are removed. Regression coverage checks that legacy configuration cannot touch a host directory, bind a compatibility port or change the panel contract. Existing isolated tests cover profiles, allowed combinations, thumbnails, language, appearance ownership and recovery. Historical checks below apply only to their named versions. Current release execution evidence is recorded separately.

## Package 0.5.2

The default downloadable profile, bilingual complete JSON examples, panel preview and native-page prototype now use Lulu. The panel was exercised against an isolated loopback service: orange bag on/off, pajamas and cardboard dinosaur selections applied correctly, Chinese/English switching worked, and the actual download contained `lulu-capybara` with the four schemes `bag`, `plain`, `sleep` and `dino`. The new screenshot shows that real panel preview. The prototype served each of the four approved still images byte-for-byte and selected its Lulu preview factory while keeping the installed host files read-only. Its static preview is separate from the complete animated figure release.

The previous character's example JSON and procedural artwork have been removed from the current source. General multi-control, incomplete-matrix and lifecycle coverage remains in neutral isolated fixtures.

## Package 0.4.0

Twenty-six isolated tests pass locally, including seven native-adapter tests for exact anchors, unknown-source refusal, backup/rollback and repeated stop, interrupted installation recovery, external page changes, helper collisions and read-only feed origin/token checks. Disposable original fixtures substitute for the host source only inside the tests; the production adapter requires the documented exact checksum. The 0.3 checks below remain relevant to the separate panel. The optional adapter has a narrow compatibility boundary, not general host API support.

## Package 0.3.0

The initial local checks ran on Windows with Node.js 26.3.1. No runtime dependency installation was required. The packaged World was also installed and activated in a real Coopanion 0.2.17/Core deployment with the person's permission.

- Nineteen isolated tests use actual loopback HTTP servers and temporary directories. They exercise outfit-specific choices, incomplete resource matrices, profile boundaries, default construction, apply/stop restoration, external choices, preference preservation, interrupted-write recovery, serialized requests, origin restrictions, reinstall and unavailable-service reporting read-only thumbnail path/origin restrictions, non-writing profile checks, UTF-8 size limits and the documented/downloaded profile examples and isolated language preference persistence.
- The official `cortico@0.2.12` manifest parser, `dryMountWorld` and `checkDescribe` accepted the extension with no warnings or failures. These checks construct a World in a fake deployment without calling `start()`; they verify the official declaration contract, not full host runtime integration.
- The 0.3 manual/download/check UI was exercised with isolated fixture data, including Chinese/English switching, saved language after reload and preservation of the pending outfit/JSON draft, including a narrow viewport with no horizontal overflow. Native-window stale provider metadata was reproduced and cleared by recreating the settings window; this is a page-refresh procedure, not a host-code patch. The panel uses the host theme, a dotted stage and compact outfit cards. A narrow window was checked for horizontal overflow. The actual panel client was opened in a browser against an isolated local service with an isolated character fixture. Manual interactions verified different control groups, applying choices, restoring the previous appearance and reading the authoring guide.
- The real Core panel was manually checked for outfit-specific controls and applying existing appearances. Disabling the World restored its owned appearance; reactivating it preserved local profiles. The existing figure files retained their recorded release hashes. Deployment names, profiles and screenshots from that check are private and are not included here.
- Package inspection uses an explicit file allowlist, scans for common private-path/credential patterns and checks archive size. Manual content and screenshot review remain required. The current screenshot shows only the authorized Lulu example.

CI is configured for Node.js 22 and 24 on Windows and Linux. Check the repository's workflow results for their status. A full package removal/reinstall was not run in the live deployment; normal disable restoration was checked there, and recreation/profile persistence is covered by the isolated tests. This is an initial experimental release rather than an unrestricted compatibility claim.
