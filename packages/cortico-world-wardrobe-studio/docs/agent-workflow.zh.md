# 从零制作自己的角色与装扮

本手册也在扩展内显示。所有例子仅使用虚构角色“苔星狐”。本扩展提供指导、衣橱配置校验和外观切换；生图、视频生成、抠像及角色运行时代码需要使用你选择的其他工具。

## [plan] 1. 明确交付物与工具

最终需要两种不同的文件：能够播放动作的“形象资源包”，以及给已有搭配分组的“衣橱配置 JSON”。衣橱 JSON 不是角色资源包，导入它不会安装视频、自动换衣或生成动作。

1. 已有角色新增服装：先盘点 figure.json、入口脚本、装扮 ID、动作词汇和播放器，在私有副本中扩展资源。全新角色：先完成并验收 figure API 2 资源包，再给外观分组。
2. 确定身份、轮廓线、比例、画风、镜头和桌面实际显示大小。分别定义每套服装的配置项，例如苔星狐的探险装有斗篷和足部装备，观星装只有护目镜。只列出准备实际制作的完整搭配。
3. 为每个完整搭配建立动作清单：一次性动作、循环动作、左右行走／跑步、坐定姿态和独立表情。以目标运行时真正支持的能力为准，没有统一的必需动作数量。
4. 盘点已有生图工具、连续视频工作流、抠像工具、显存和磁盘。复用已验证环境；下载大模型或修改环境前先取得同意，私下记录版本、安装位置、磁盘变更和卸载回退步骤。
5. 先拿一个搭配、一个短动作打通原视频、抠像和实际桌宠播放，再扩大制作范围。

建议私有目录如下。这是整理建议，不是扩展导入格式：

```text
character-project/
  project.json                 角色设定、搭配／动作清单、版本
  references/<scheme>/v001.png
  recipes/<scheme>/<action>/v001.json
  raw/<scheme>/<action>/v001.webm
  reviews/<scheme>/<action>/v001.json
  alpha/<scheme>/<action>/v001/000000.png
  staged-figure/               manifest、运行时、已验收素材
  wardrobe.json                导入扩展的分组映射
```

保留源文件和已验收版本。完整未压缩帧只保留必要缓存，不为每个预览重复保存整套帧。公开仓库不包含个人制作工程。

## [reference] 2. 先定稿完整穿衣参考图

输入：已经确认的人物／画风参考和一套完整服装设计。输出：每个有效搭配的一张完整穿衣角色图，有侧向动作时补充相应方向参考。

1. 参考主图建议保存 PNG。768 × 1152 竖图可作为起点，并非扩展硬性尺寸；实际视频工作流可能要求其他分辨率。头发、双手和双脚完整入镜，四周保留余量。
2. 不同搭配保持同一镜头高度、构图、比例、轮廓线和材质画法，采用中性站姿。白底能够稳定生成时使用纯白背景，不带投影、地面线、文字和水印。
3. 检查脸与头发身份、肢体连接、衣服结构、配件位置和重复标记朝向。浅色服装要有清晰绘制边界；不能把白色布料和白色背景混为一体。正侧视图必须是同一设计。
4. 整张完整角色图验收后再生成动作，记录版本和 SHA256。新参考定稿后，不用旧试验图覆盖。

可调整的参考图提示词：

```text
与已确认身份参考相同的虚构苔星狐：橙色皮毛、奶油色口鼻，
清楚的深色卡通轮廓线、简洁明暗和统一头身比例。
穿已确认的叶绿色探险斗篷和棕色步行靴，服装与角色画风一致。
全身、中性放松站姿、手脚完整可见、固定平视镜头、竖向居中构图，
纯白背景，没有地面投影、文字或水印。保持脸、毛发与身体比例一致。
```

通常使用一张完整角色图作为身份输入，动作视频作为动作输入。除非工作流明确支持，不把多姿势拼图送进单人物图生视频参考口。

## [video] 3. 生成一个完整连续动作

输入：已验收的完整穿衣图、动作参考视频、已保存的兼容工作流。输出：完整连续原视频，保留原始画面与时序。

1. 动作参考只有一个角色，固定镜头，全身可见，类型、方向、节奏清楚，简单白底。裁掉无关前后内容，但保留完整动作。时长、帧率和帧数遵循实际工作流，不截掉落地或回归静止部分。
2. 使用已跑通的 SCAIL-2 时，完整穿衣图接到角色／参考图输入，动作视频接到动作驱动输入。核对本机节点版本的真实名称和输入预览，保存完整 API 工作流与节点／模型版本。不同节点版本不能保证通用同一份工作流 JSON。
3. 已有兼容且通过验证的加速配方时，先用 8 步、CFG=1、shift=1、对应加速 LoRA 强度=1。这是经过验证的起点，不代表任意模型与 LoRA 兼容，也不能悄悄下载缺失权重。
4. 每个新动作先最多三版加速配置；仍不合格再最多两版原始非加速 20 步；诊断后才考虑 40 步。切换时同时恢复完整 CFG、shift 和 LoRA，不能只改步数。一个动作失败不代表其他动作都要加步，已合格的高步数素材继续保留。
5. 动作参考只约束类型、朝向和节奏，允许新衣服的轨迹、遮挡、布料运动自然变化。完整穿衣主体通过连续视频生成，不用逐帧独立生图、贴图替换、光流搬运或简单拉伸拼出服装。

可调整的连续动作提示词：

```text
始终是参考图中的同一只完整穿衣苔星狐，脸、皮毛、斗篷、靴子、
清晰卡通轮廓和身体比例保持一致。按照参考节奏完成一次友好挥手：
中性站姿开始，抬起一侧前臂，自然挥手，放下手臂，回到相同中性站姿。
固定镜头和角色大小，全身完整入镜，纯白背景。
斗篷随肩臂自然运动，双手完整并与手臂正常连接。
```

记录完整工作流、模型／LoRA 哈希、提示词、参考哈希、种子、步数、CFG、shift、尺寸、帧率、帧数、耗时和重试原因。512 × 768、24 fps 只是工作流参数示例，不是衣橱导入要求；视频帧数遵循实际模型约束。

## [review] 4. 先验收原始视频

1. 每条完整观看原速与半速。循环动作在两种速度下各连续至少三轮，先以桌宠实际大小观察，需要诊断时再放大。
2. 检查身份、服装设计／颜色、比例、手脚连接、遮挡、身体／布料缺失、闪烁、异常色块、镜头／背景稳定和首尾状态。挥手回归预定静止，跳跃要有落地，行走要有正确朝向。
3. 两种速度和循环接缝分别填写具体观察、通过／失败。抽帧、拼图、指标不能代填播放验收，没有完整看过的保持“待验收”。
4. 先找原因再重试：核对身份图、动作输入、遮罩（若使用）、节点兼容和提示词，再在限定次数内针对性修改。难解决动作独立标记待处理，不能换成错误动作冒充完成。

私有验收记录示例。这是工程整理建议，不是扩展 JSON：

```json
{
  "scheme": "trailleafboots",
  "action": "wave",
  "version": "v001",
  "sourceSha256": "<填写真实的64位十六进制SHA256>",
  "width": 512,
  "height": 768,
  "fps": 24,
  "frameCount": 73,
  "loop": false,
  "normalSpeed": {"result": "pending", "observation": ""},
  "halfSpeed": {"result": "pending", "observation": ""},
  "loopJoin": {"result": "not-applicable", "observation": "一次性动作"},
  "decision": "pending"
}
```

参数从实际文件读取，不照抄示例。合格原视频下载时保留原尺寸、帧率和完整时长，校验传输 SHA256，再提取透明素材。

## [matte] 5. 本地连续抠像

输入：通过播放验收的原视频。输出：保持原人物 RGB、时间连续的透明度序列，以及完整多背景播放检查。

1. 按源时间解码。确认恒定帧率时不再采样或发明帧；可变帧率要保留时间戳，或先明确转换为恒定帧率、记录转换并重新验收动作。
2. 用已有本地小工具（如 SAM2 tiny）得到首帧前景建议，明确添加前景／背景点，人工检查；可用 GrabCut 细化种子遮罩。这些是独立工具流程，不是扩展内置的一键抠图按钮。
3. 浅色衣料标为前景，手臂与身体之间的白色空隙标为背景。分别检查封闭的腋下／手臂间隙、腿与衣物间隙、外轮廓，不能仅凭白色阈值区分。
4. 用 MatAnyone2 或其他已验收视频抠像流程传播透明度。后续才出现的空隙，按工具支持的方法在合适关键帧纠正，再传播相应片段，不逐帧独立重绘人物。
5. 保留原 RGB 和合理抗锯齿，同时检查白色污染；确认布料误删后，只在真实原边界内恢复透明度，不用染黑白衣料掩盖遮罩问题。
6. 保存同一画布的无损 RGBA PNG 序列，连续命名，统一 alpha 约定（通常为 straight alpha），记录帧数、帧率和时间。JPEG 不支持透明度；不要逐帧自动裁边或各自平移居中。
7. 在深灰、饱和紫／绿和棋盘格背景上，完整观看原速、半速和循环接缝。检查残留背景岛、误删衣料、白边、边缘闪烁、肢体间隙和位置抖动。首帧或缩略拼图不能代替整条验收。

已有 FFmpeg 且确认源视频恒定帧率时，可这样抽帧；先创建输出目录：

```sh
ffmpeg -i raw.webm -fps_mode passthrough frames/%06d.png
```

命令只抽取 RGB，不会自动去背景。保留一份工作缓存和合格透明主素材，不为每个预览重复存整套帧。

## [runtime] 6. 制作真正能播放的形象包

透明帧和衣橱 JSON 本身不会动，仍需实现宿主形象运行时。已有兼容角色可在私有副本中按其播放器规则扩展映射；从零制作时先实现、测试本机安装版本的 figure API。

当前 figure API 2 工厂接口：

```text
exportedFactory(base, { model, scheme, kit, loadImage, asset, host })
  -> 必需包含 step(dt)、layout()、do(word) 的 body
```

宿主从 figure.json 的 entry 加载模块，调用 export 指定的工厂，提供本地资源解析与绘制根元素。只声明真正实现的词。行走还需要宿主所用的 walk／stop、layout、事件行为，绘制方法不等于移动。新播放器应核对当前 figure-frame.js 和 kit/body.js 契约。

目录与 manifest 骨架如下，不是已完成的动画播放器：

```text
forest-fox/
  figure.json
  figure.js             实现并导出 createFoxBody
  model.json            自己播放器的动作映射（若使用）
  thumbs/trail.png
  thumbs/rain.png
  clips/<scheme>/<action>/000000.png
```

```json
{
  "manifest": 2,
  "api": 2,
  "id": "forest-fox",
  "version": "1.0.0",
  "name": {"en": "Moss Fox", "zh": "苔星狐"},
  "about": {"en": "A fictional cartoon forest fox.", "zh": "虚构的森林狐狸。"},
  "entry": "figure.js",
  "export": "createFoxBody",
  "model": "model.json",
  "thumb": "thumbs/trail.png",
  "axes": [{
    "id": "appearance",
    "name": {"en": "Appearance", "zh": "完整外观"},
    "options": [
      {"id": "trailleafboots", "name": {"en": "Trail"}, "thumb": "thumbs/trail.png"},
      {"id": "rainupgold", "name": {"en": "Rain"}, "thumb": "thumbs/rain.png"}
    ]
  }],
  "vocab": [],
  "can": {"walk": false}
}
```

骨架故意不声明已完成动作，实现后再填写真实 vocab 和移动能力。model.json 是自己播放器的数据，不是宿主通用视频清单。沙箱不保证直接支持 MP4／WebM，要核对当前 CSP／资源策略，或采用已验证的图片帧播放器。模块、资源放在包内，不依赖外部 CDN。

每条动作使用固定的整体等比变换和地面锚点，侧向行走／跑步伴随实际横向移动。检查左右、短长距离、起步停步、转向、落地、坐下起身、换装，不逐帧重新裁边／居中。

运动视频保留原生面部，除非另有通过验收的时间连续表情方法。站立／坐定表情使用本姿态测量锚点，逐套检查每个声明表情；注册进列表不代表视觉覆盖完整。

通过宿主形象导入器安装暂存包，先在真正桌宠中验证，确认本机列表能读取它、每个目标 scheme 正常播放，再导入“衣橱 JSON”章节的映射。

## [release] 7. 整理、导入与交付

1. 保留合格参考、完整工作流、原视频、哈希、耗时／费用和真实播放观察；失败版本只保留必要素材及失败／重试原因。
2. 替换前在真实沙箱校验暂存包，备份原包和外观设置，可回退安装，不悄悄改写内置角色。
3. 创建 schema=1 衣橱配置，figure 填已安装包 ID，每个 variant 指向已有 scheme。先“校验配置”再导入；这里只校验结构／ID，不等于视频已验收或动作齐全。
4. 检查每套服装的独立选项、有效组合、应用、原生页外部选择、恢复、停用和重启。卸载本扩展前，在桌宠服务可用时先恢复并确认。
5. 交付合格原视频／透明素材、可运行形象包、本机衣橱 JSON、动作／表情覆盖和回退说明。个人参考、配置留在公开扩展仓库之外。
6. 公开工具仅包含通用源码、说明和完全虚构示例。检查确切 npm 包及 Git 历史，排除个人角色／服装名、素材、机器路径、凭证、服务器地址和聊天记录。传输校验 SHA256。指南写的是要求，实际制作记录才证明已通过验收。
